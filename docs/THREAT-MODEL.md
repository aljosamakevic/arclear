# Arclear threat model

## Trust model, stated plainly

- **Safety** (no balance moves without its owner's signed consent over the
  exact full position set) is enforced **on-chain**, unconditionally.
- **Liveness** (rounds actually happen) is bounded by v2's threshold
  consent (PROTOCOL.md "Threshold consent"): non-consenters are excluded in
  one deterministic batch and the round rebuilds from the consenting subset
  — at most two signature-collection passes per attempt. v1 traded liveness
  for simplicity; v2 caps the cost of a stall at rebuild latency.
- **Counterparty credit** between rounds is bounded **off-chain** by bilateral
  credit caps (`src/creditCap.ts`): a creditor stops serving a debtor whose
  unsettled paper exceeds the cap. Worst-case loss per counterparty = the cap.
- **Recovery** (v3): a creditor holding a signed IOU from a debtor absent
  from the last ≥ K executed rounds can redeem it directly against the
  debtor's posted collateral (`redeemIOU`, PROTOCOL.md "IOU redemption") —
  **best-effort by design**: it recovers posted, still-present collateral
  only and races the never-pausable `withdraw`. Credit caps remain the
  exposure bound; redemption is not insurance.
  **On the V3 hubs the guarantee is real again**: exclusivity is one permanent
  `consumed[leafId]` read, and the only way that bit gets set is a round in
  which both of the IOU's parties signed. No third party can manufacture it,
  erode it, or time it out. **On the still-deployed V2 hubs it is not** — rows
  28 and 29 below let any address permanently disable `redeemIOU` there, for
  one chosen IOU or for every IOU on the hub at once, for a few hundred
  thousand gas and no collateral. If you are pointed at a V2 hub, size credit
  on caps + posted collateral alone.
- The coordinator is a convenience relay with no keys and no authority — v2
  and v3 add it none: the redemption gate reads on-chain executed-round
  staleness, never coordinator attestations.

**Contract generations, and which rows apply.** `ClearingHubV3` +
`PvPRouterV3` are the current deployments and are what unqualified statements
here describe. `ClearingHub` (v1), `ClearingHubV2` and `PvPRouter` (V2) remain
deployed on Arc Testnet; rows that are version-specific say so explicitly.

## Attack surface checklist

| # | Attack | Defense | Test |
|---|--------|---------|------|
| 1 | Replay an executed round | on-chain `roundNonce` check + increment | `test_revert_replaySameRound` |
| 2 | Replay a signature across hubs / tokens / chains | EIP-712 domain binds `verifyingContract` (per-token hub) and `chainId` | `test_revert_crossHubReplay` |
| 3 | Count one IOU twice in a netting | dedup by `iouId`; per-pair monotonic nonces make duplicates identical | vitest property: multiset == set |
| 4 | Re-net an IOU already settled in a prior round | coordinator excludes ids in executed manifests; `manifestHash` makes violations provable after the fact | coordinator `settledIds` + e2e |
| 5 | Malicious coordinator proposes wrong positions | dies by construction: every participant signs the same full-set digest and `verifyProposal` recomputes locally — never trusts | `test_revert_tamperedDelta`, `test_revert_tamperedManifest` |
| 6 | Forge or substitute a consent | ECDSA recovery must equal the participant at the same index | `test_revert_missingConsent`, fuzz perturbation |
| 7 | Grief by stalling or refusing to sign | threshold consent (v2): timeouts and reasoned refusals are excluded in one deterministic batch and the round rebuilds from the consenting subset — worst case two collection passes, a latency cost, never a safety cost. A reasoned refusal (`verifyProposal` fails locally) is the safety mechanism working and does **not** count as a missed window; only timeouts advance the miss counter. Bilateral credit caps still bound the refuser's paper | rebuild property tests (`test/rebuild.test.ts`); e2e liveness scenario (`npm run e2e:anvil`); griefing analysis in PROTOCOL.md |
| 8 | Withdraw collateral between consent and execution | round reverts **in full** — equivalent to refusing consent; never partial settlement | `test_revert_withdrawFrontRunsExecution` |
| 9 | Sneak a duplicate participant / unsorted set | strictly-ascending check (one O(n) pass) | `test_revert_duplicateParticipant`, `test_revert_unsortedParticipants` |
| 10 | Signature malleability | OpenZeppelin ECDSA rejects high-s values | fuzz perturbation test |
| 11 | Rounding games | impossible: integer add/sub in base units; no division exists in the protocol | — |
| 12 | Fee-on-transfer / weird ERC-20s | SafeERC20 everywhere; fee-on-transfer explicitly unsupported (documented) | — |
| 13 | Owner rug | owner can only pause deposits+rounds+redemptions; **withdrawals are never pausable**, no upgradeability, no fee switch, no access to funds | `test_withdraw_worksWhilePaused`, `test_withdraw_worksWhilePaused_V2`, `test_withdraw_worksWhilePaused_V3`, `test_pause_onlyOwner` |
| 13b | Owner bricks the hub by renouncing while paused (v3) | renouncing would make `unpause` permanently unreachable, killing deposits, rounds and redemption forever — withdrawal survives, so funds could never be trapped, but the protocol would be dead. `ClearingHubV3.renounceOwnership` reverts `RenounceDisabled` (audit WR-06); ownership can still be handed to a multisig or timelock via the two-step transfer | `test_revert_renounceOwnership_disabled`, `test_transferOwnership_stillWorks` |
| 14 | Merkle second-preimage (internal node replayed as a leaf, or cross-domain confusion) | RFC 6962-style `0x00`/`0x01` prefix domain separation on every leaf/node hash; EIP-712 digests (`\x19\x01`-prefixed) cannot collide with either domain | TS↔Solidity parity fixtures (`test/fixtures/merkle.json`) incl. negative vectors; `MerkleParity.t.sol` |
| 15 | Double-claim, net → redeem (redeem an IOU a round already consumed) | **v3: one permanent storage read.** `redeemIOU` reverts `IouAlreadyNetted` iff `consumed[manifestLeafId(id, debtor, creditor)]` is set. The ledger is written by `executeRound` for every consumed ref and nothing ever evicts, expires or rewrites an entry, so the check is O(1), history-independent, and cannot be defeated by any amount of subsequent activity. V2's L-bounded coverage rule and per-root non-inclusion proofs are gone — see rows 28/29 for why they had to be | `test_revert_redeemIOU_alreadyNetted`, `test_revert_executeRound_alreadyConsumedAcrossRounds`, e2e redemption scenario |
| 16 | Double-claim, redeem → net (settle a redeemed IOU in a later round) | nullifier keyed by the raw IOU id; `executeRound` reverts `NullifiedIdInManifest` on any consumed ref whose id is nullified; coordinator folds `IouRedeemed` logs into netting exclusions | `test_revert_executeRound_nullifiedId`, `testFuzz_redeemNullifierIdempotent` (512 runs, balances frozen), e2e permanent-exclusion tail |
| 16b | Settle the same obligation in two different rounds (v3) | **now an on-chain invariant, not a coordinator convention.** `executeRound` reverts `AlreadyConsumed(leafId)` if any derived leaf is already in the ledger. Under V2 one id could appear in unlimited manifests and "one IOU, one settlement" rested entirely on off-chain `settledIds` bookkeeping (audit IN-05) | `test_revert_executeRound_alreadyConsumedAcrossRounds`, `test_poc_sameIouCannotBeNettedTwice` |
| 17 | Forged position claims (lying `index`/`leafCount` to fake a bracketing non-inclusion) | **v3: not on any protocol path.** `redeemIOU` takes no proofs, and nothing in the SDK, the demo or either V3 contract generates or verifies a non-inclusion proof. The encoding stays frozen in `ManifestMerkle.sol` + `src/merkle.ts` only so the shared fixture keeps cross-checking a live dual implementation; the analysis below is retained as documentation of that frozen encoding. It still governs anyone reading a V2 hub's proofs. **`leafCount` is NOT bound by the root** — many leaf counts share one sibling-consumption schedule (a genuine 4-leaf root verifies a proof claiming `leafCount = 3` at index 0 and at index 1; enumerating all `(index, leafCount)` for n ≤ 64 gives 127 distinct schedules of which **123 are shared across two or more leaf counts**). What is bound is the schedule itself: reaching the root from a genuine leaf hash requires replaying that leaf's exact left/right sibling-consumption sequence, so a lie that *changes* the schedule needs a keccak second preimage. Soundness comes from the **kind-specific index constraints** interacting with that schedule, not from `leafCount` being trustworthy: `BelowFirst` forces claimed index 0, whose schedule is all right-consumptions, and the only real leaf whose schedule is all right-consumptions is leaf 0; `AboveLast` forces claimed index `leafCount − 1`, whose schedule never contains a right-consumption, and every non-last real leaf's schedule ends in one; `Bracket` forces one shared claimed `leafCount` and consecutive claimed indices. Exhaustive enumeration finds **zero** false `BelowFirst`, `AboveLast` or `Bracket` candidates (real n ≤ 64 against claimed leaf counts ≤ 4096 for the two boundary kinds, ≤ 256 for brackets). **Consequence to respect:** any *new* `NonInclusionKind`, or any caller that reads `leafCount` as "this manifest has exactly N leaves", would be unsound and no current test would catch it | `testFuzz_redeemProofPerturbation_reverts`, `testFuzz_redeemProofSetSkip_reverts` (512 runs each), fast-check adversarial properties, `ManifestMerkle.t.sol` anchor/adjacency negatives |
| 18 | Keep-alive censorship griefing (live debtor dust-cycles to keep `lastRound` fresh while censoring one creditor) | **documented limitation, accepted**: visible on-chain, costs the debtor gas every round, out of protocol scope to punish in the Net product; credit caps are the creditor's defense (PROTOCOL.md griefing analysis) | — |
| 19 | Debtor exit race (withdraw free collateral before redemption lands) | **unfixable by design** — `withdraw` is never pausable and must not be; redemption is best-effort recovery of posted, still-present collateral, documented plainly | withdraw-race honesty test (`redeemIOU` reverts `InsufficientCollateral` after exit) |
| 20 | Proof-set TOCTOU (round executes between proof generation and redemption mining) | **removed with the surface (v3).** There is no proof to invalidate: exclusivity is a single `consumed[leafId]` read whose answer is monotone and permanent, so a round landing between a creditor's decision and their transaction being mined can only ever make the redemption *fail closed* by legitimately consuming the IOU. V2's mitigation — contract-derived proof sets positionally matched to `roundNonce`/`RING` — was correct but is now moot | n/a (V2: `testFuzz_redeemProofSetSkip_reverts`, `ProofCountMismatch` revert tests) |
| 20b | Nonce-paced staleness griefing (pay for rounds to move the redemption clock) | **accepted and documented, not closed.** The staleness gate counts rounds, not seconds. A debtor refreshes their own `lastRound` by settling or consuming *something* — WR-11 raised the price from "co-sign anything" to a cold SSTORE per fabricated ref, but the contract cannot tell fabricated paper from real. Symmetrically, a third party can accelerate everyone else's staleness by paying for rounds. Both are inherent to a round-counted clock; **neither moves collateral without the affected party's signature**, so this shifts *when* the recovery window opens, never *whether* consent was given. `EmptyRound` at least removes the completely free no-op round | `test_poc5a_coSigningNoLongerResetsClock` (WR-11 working), `test_poc5b_residual_fabricatedRefStillResetsClock` and `test_poc_residual_thirdPartyCanAccelerateStaleness` (both directions pinned as accepted behaviour), `test_revert_executeRound_emptyRound`; PROTOCOL.md "Residual risks V3 does not close" |
| 21 | Single-leg extraction (an adversary obtains one leg's complete Round signature set — including by extracting the pending router transaction's calldata from the mempool — and submits that leg directly via `executeRound`, settling it without its twin) | **accepted and documented**: PvP both-or-neither holds within the router path and against all failure/revert modes; it does not hold against unilateral submission of one leg's full signature set. The downgrade is to standard netting credit risk, never to unsigned movement — the settled leg moved exactly as its participants unanimously signed it, and the open leg's obligations persist as collateral-backed, redeemable IOUs. Custody discipline narrows the window: the coordinator is the only party ever holding a complete leg signature set and publishes leg signatures only inside the router transaction | `test_singleLegDirectSubmissionSettles` (machine documentation: the bare submission settles, then the router bundle reverts `WrongRoundNonce`) |
| 22 | Evil-hub substitution (route one real leg and one fake leg through the router by pointing it at a malicious "hub") | structurally closed: the hub pair is fixed as **constructor immutables** — no calldata hub addresses exist anywhere in `executePvP`, and `verifyingContract` = the router binds every PvPRound signature to exactly that hub pair | `test_constructor_immutables`; no calldata hub parameter to attack |
| 23 | Leg/digest mismatch (execute calldata legs that differ from what the union signed) | each leg digest is recomputed on-chain via that hub's public, parity-locked `hashRound` over the calldata leg and must equal the signed digest before any execution — revert `LegDigestMismatch` | `test_revert_executePvP_legDigestMismatch` |
| 24 | PvPRound replay (re-submit an executed bundle) | structural, zero router state: each signed leg digest binds its hub's `roundNonce`; once either leg executes (by any path), re-execution reverts `WrongRoundNonce` and takes the bundle with it | `test_revert_executePvP_replaySameBundle` |
| 25 | FX-rate manipulation (coordinator proposes a bad rate) | the rate is **agreed, not oracle-derived** — there is no oracle to manipulate. It is bound into the PvPRound digest that every union member signs after `verifyPvPProposal` checks each shared-`ref` FX pair by bigint cross-multiplication AND per-pair inclusion symmetry (row 27); a bad rate dies at local verification, and unanimous consent bounds what any coordinator can push | `test_hashPvPRound_fieldSensitivity`; `verifyPvPProposal` rate-mismatch rejection tests (`test/pvp.test.ts`) |
| 26 | PvP signature malleability | OpenZeppelin `ECDSA.recover` on every PvPRound signature (rejects high-s), same as the hubs' Round consents | `test_revert_executePvP_badPvPSignature` |
| 27 | Counter-leg stripping (coordinator consumes a member's paying IOU on one leg while omitting their receiving counter-IOU from the other leg, padding that leg with unrelated paper to keep quorum — settling one side of the member's trade) | caught at local verification: `verifyPvPProposal` enforces per-`ref` FX-pair **inclusion symmetry** — for every shared-`ref` pair the member holds, both sides must be jointly consumed or jointly deferred by the proposed legs. The per-leg `verifyProposal` cannot see this (the member was stripped from the counter-leg entirely, so that leg's check never runs), so the cross-leg symmetry check is the guard; a coordinator-constructed one-sided settlement dies as a refusal-for-cause before any consent is signed. This is what makes "a malicious coordinator dies by construction" hold for the member's *trade*, not just for each *leg* | CR-01 regression test in `test/pvp.test.ts` (both stripping directions, quorum-padded) |
| 28 | **Manifest poisoning — permanently disable `redeemIOU` for a chosen IOU** (write a victim's IOU id into a round's manifest) | **CLOSED BY CONTRACT CHANGE IN V3. STILL LIVE ON THE V2 HUBS.** *The V2 flaw:* `executeRound` never bound a consumed id to the round's participants — no debtor/creditor recovery, no ownership check, no consumption ledger; the only constraints were strict ascent and "not already redeemed". And a round was free (`n = 2`, `deltas = [0, 0]`, the `delta >= 0` branch needs no collateral, no IOU has to exist), so any two throwaway addresses could commit a manifest containing any id. `redeemIOU` then demanded a non-inclusion proof against every buffered root, and no such proof exists for a genuine leaf. The debtor was the natural attacker: they know every id they ever signed, and one transaction listing all of them immunised them forever. Measured on V2 (`gasleft()` deltas, excluding ~21k intrinsic): 136,762 gas for a first free round with an empty manifest, ~3,808 per additional poisoned id. *The V3 fix:* the manifest entry is a party-bound `ConsumedRef`, and the committed leaf is `manifestLeafId(id, partyA, partyB)` over two **listed participants** — every one of whom signs the round digest. A poisoner pairing a victim's id with their own addresses derives a **different** key that can never collide with the honest leaf and that no honest redemption reads. Consuming real paper requires the **creditor's** signature, and a creditor will not sign away their own claim unpaid, so the attack is economically inert, not merely expensive. **What was NOT affected either way:** settlement safety, zero-sum and the signed-consent invariant — a poisoning round moves no balance, because every delta is zero and each participant still signed. The damage was confined to the recovery product | V2: reproduced against the shipped contract during the 2026-07-27 audit. V3: `ClearingHubV3PoC.t.sol` — `test_poc1_manifestPoisoningNoLongerBlocksRedemption`, `test_poc1b_debtorSelfPoisonIsInert`, `test_poc1c_ledgerKeyMustBePartyBound`, `test_poc1d_genuineConsumptionStillBlocksRedemption`; plus `test_revert_executeRound_partyIndexOutOfRange`, `test_revert_executeRound_selfConsumedRef`, `MerkleParityV3.t.sol` leaf-derivation parity |
| 29 | **Ring flush — permanently disable `redeemIOU` for every outstanding IOU on a hub** (advance `roundNonce` with free rounds until the root ring's oldest `executedAt` passes every IOU's coverage window) | **CLOSED BY CONTRACT CHANGE IN V3. STILL LIVE ON THE V2 HUBS.** *The V2 flaw:* `executeRound` unconditionally wrote `rootRing[nonce % RING] = (root, nonce, block.timestamp)` and incremented `roundNonce`. Combined with the free round above, any address pair could overwrite all 16 ring slots with the current timestamp. The coverage gate reverted when `oldestExecutedAt >= expiry − L`; `oldestExecutedAt` only ever increases while `expiry − L` is fixed by the IOU, so once pushed past that line **the IOU could never be redeemed again.** Global, not per-victim: one attacker with no relationship to anyone killed redemption for every IOU on the hub simultaneously. Measured on V2: 1,053,610 gas to flush all 16 slots (~65.9k per round), verified still reverting after warping seven days forward. It survived a fix to row 28 — it attacked the ring, not the manifest. *The V3 fix:* pricing rounds up would not have worked (the window is compressible by anyone willing to pay, and no guard that keeps a ring makes it uncompressible without capping throughput), so **the ring is deleted**. Redemption reads a permanent `consumed[leafId]` ledger instead: nothing to flush, nothing to buffer, no coverage rule, no `L`. Two further audit findings went with the surface — WR-01 (a `leafCount` large enough to panic the verifier) and WR-03 (the coverage rule penalising short-lived, therefore safer, IOUs). **What was NOT affected either way:** as row 28 | V2: reproduced against the shipped contract during the 2026-07-27 audit (permanence verified 7 days later). V3: `test_poc2_ringFlushSurfaceIsGone`, `test_poc2b_flushIsIneffectiveAcrossTime`, `test_gas_v3_redeemIOU_isHistoryIndependent` (execution gas exactly equal after 4 and 64 rounds), `test_revert_executeRound_emptyRound` |
| 30 | Consenting to a round that lists your obligation under somebody else's party pair (v3) | **chain-safe, and refused as data.** Such a leaf is not yours, so the hub never marks *your* obligation consumed and your IOU stays redeemable — the hazard is that you would have consented to a round claiming to have netted it. `verifyProposal` recomputes every entry's leaf from its stated parties, rejects a cached `leafId` that does not bind them, and requires every obligation of yours that your own recomputation consumed to appear in the manifest **under its own party pair** | `test/forgedId.test.ts` (attribution + omission cases); `test/verifyTotality.test.ts` (a malformed manifest is a reasoned refusal, never a throw) |

## Known limitations and their answers

| Limitation | Consequence | Status / answer |
|---|---|---|
| Unanimous consent over the candidate set | one stalled participant delays settlement (funds never at risk) | **shipped in v2**: threshold consent — non-consenters are **excluded and recomputed**, never outvoted; the final executed set still signs unanimously; worst case two collection passes (PROTOCOL.md "Threshold consent") |
| Plain-hash manifest | no efficient per-IOU proofs | **shipped in v2**: sorted-leaf merkle root in the same `bytes32` field, derived on-chain from calldata, so every round's leaf set is publicly reconstructible without a coordinator. **v3 kept the commitment and changed the leaf** to `manifestLeafId(id, debtor, creditor)`, which is what makes a manifest entry attributable at all (PROTOCOL.md "Manifest commitment") |
| No on-chain IOU redemption | a vanished counterparty's paper was only recoverable socially; loss bounded by credit caps | **shipped in v2, defeatable there, redesigned in v3.** `redeemIOU(iou, sig)` recovers against the debtor's posted collateral, gated by on-chain staleness — the debtor absent from the last ≥ K **executed rounds** (never coordinator attestations; the coordinator's miss counters are an off-chain early-warning signal only) — plus a single permanent `consumed[leafId]` read. No proofs, no ring, no coverage window, O(1) and history-independent. Still best-effort: it races the never-pausable `withdraw`, and credit caps remain the exposure bound (PROTOCOL.md "IOU redemption") |
| **Manifest poisoning — redemption griefable per IOU** (attack-surface row 28) | on V2, any address could write a victim's IOU id into a free round's manifest and no non-inclusion proof for a genuine leaf can exist, so that IOU became permanently unredeemable. The debtor was the natural attacker: one transaction listing every id they ever signed immunised them for good, at ~3,808 gas per id on top of a ~137k-gas free round | **FIXED IN V3 — party-bound leaves.** It could never be fixed off-chain (no SDK or coordinator change restores redemption, and `ClearingHubV2` is immutable), so the fix was the contract revision that shipped: bind each consumed entry to two **listed, signing** participants and key the ledger on that bound leaf. A poisoner's write now lands on a key no honest redemption reads. **The V2 hubs remain deployed and remain affected** — treat `redeemIOU` there as worth zero. What it never touched, on either version: settlement safety, zero-sum, and the signed-consent invariant |
| **Free rounds flush the root ring — redemption griefable hub-wide** (attack-surface row 29) | on V2, every `executeRound` rewrote a ring slot's `executedAt` and incremented `roundNonce`, and rounds were free, so ~1.05M gas of empty rounds pushed the oldest buffered `executedAt` past every outstanding IOU's `expiry − L` — permanently, verified still-reverting a week later. One attacker with no relationship to any member killed redemption for every IOU on the hub at once | **FIXED IN V3 — the ring is deleted.** Making rounds non-free would not have sufficed: the window is compressible by anyone willing to pay. Replacing the coverage rule with a permanent consumption ledger removes the attack surface rather than pricing it. **The V2 hubs remain deployed and remain affected.** Same non-impact as the row above |
| **Nonce-paced staleness** (attack-surface row 20b) — *new honest residual under v3* | the staleness gate counts rounds, not seconds. A debtor can refresh their own `lastRound` by settling or consuming fabricated paper with an accomplice; a third party can accelerate everyone else's staleness by paying for rounds | **accepted and documented, not claimed closed.** Inherent to a round-counted clock: WR-11 raised the keep-alive price to a cold SSTORE per fabricated ref but the contract cannot distinguish fabricated paper from real, and `EmptyRound` removes only the completely free no-op. **Neither direction moves collateral without the affected party's signature** — this shifts *when* the recovery window opens, never *whether* consent was given |
| Off-chain credit between rounds (the tab) | a creditor holding unsettled IOUs is exposed until the next round settles or their paper is recovered | bounded and backed four ways: (1) **bilateral credit caps**, capping maximum loss to any one counterparty; (2) the debtor's **posted collateral**, which is what makes their IOUs credible; (3) **round frequency**, which shrinks the credit window; (4) **`redeemIOU`**, the collateralized recovery path against a vanished debtor (PROTOCOL.md "Capital model"). (4) is a genuine bound **on a V3 hub only** — on the V2 hubs it can still be permanently disabled by any party for a few hundred thousand gas (rows 28/29), so it must not be counted there. Even on V3 it is best-effort: it races the never-pausable `withdraw` |
| Coordinator is a single relay | availability (not integrity) depends on it | any participant can run one; gossip is a drop-in replacement |
| PvP single-leg mempool extraction | the router transaction itself publishes both legs' complete signature sets; an observer can extract one leg's calldata and front-run it as a bare `executeRound` — that leg settles, the router transaction lands second and reverts `WrongRoundNonce`, and the FX linkage for that round is lost | **accepted and documented plainly** (attack-surface row 21): the residual is Herstatt-style timing/counterparty exposure on the open leg — a downgrade from "atomically settled" to Arclear's ordinary collateralized bilateral credit, bounded by credit caps + posted collateral + `redeemIOU`, never unsigned balance movement (the claim amount is fixed in the open leg's own currency, so there is no rate exposure on the claim itself). Signature-custody rule: the coordinator alone ever holds a complete leg signature set and publishes leg signatures only inside the router transaction; participants produce leg consents only through `verifyPvPProposal` bundle context |
| Sweep evidence (docs/sweep) | at small n the worst participant's tail-case saving is ~0% | threshold consent (shipped in v2) removes the liveness blocker for larger pools — see README findings |
